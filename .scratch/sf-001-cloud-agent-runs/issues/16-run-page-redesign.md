## Answer

Done in the working copy (uncommitted, on top of `74ebf1a` and ticket 15's uncommitted changes); the prototype is removed.

- **Layout** (`routes/agent-run.tsx`): header with status, phase, spend, the previous run and cancel / re-run; left column (sticky from `md`) with the stage rail, artifact cards and run details; the conversation in the main column. One column below `md`, no horizontal scroll at 390 px; checked in light and dark on the local stack.
- **Model** (`features/agent-runs/agent-run-page.ts`, pure, table-tested): stages from `status_changed` events — queue time counts towards the next stage, an `awaiting_answer` wait towards the stage it interrupts, review stages are all waiting, repeats are numbered (`Scope v2`, `Review v2`); the run total; the conversation items (started, proposals, changes requested, acceptance, questions, withheld workflow diffs, result, delivery, how the run ended, one line per started turn); a stage jumps to the last conversation item inside it.
- **Components**: `RunRail.tsx` (stages, cards: one per pull request, Jira, spec, product intent, skills and tools, trace), `RunConversation.tsx`, `RunArtifactDrawers.tsx` (spec drawer with a version switch, product intent drawer linking to the Intent page), `RunDrawer.tsx` (the shared drawer shell, moved out of `RunActivityDrawers.tsx`). `ScopeReview.tsx` is split into `SpecDocument` (drawer) and `ScopeReviewActions` (inline on the newest proposal while the run awaits acceptance); `QuestionCard.tsx` renders the open question in place and answered ones with the chosen options marked.
- **Intent source**: the agent's intent MCP calls in the structured events. The `tool` event gains optional `intentIds` (≤ 50, `MAX_TOOL_INTENT_IDS`); the runner fills it from successful `coredoc` calls: `get_intent_context` → `matches[].id` / `entries[].id`, `intent_propose` → `items[].itemId`. `GET /:runId/activity` adds `intent: { read, proposed }` (first-seen order, deduplicated, proposed not repeated in read, ≤ 100 each), joined with `intent_items` for title, kind, authority and "Domain · Feature"; a deleted item keeps only its id. The per-turn MCP token was not usable: intent writes are audited as the token's creator (the run owner) and the token is deleted when the turn ends.
- **Trace of older runs**: runs recorded before ticket 15 have only `raw` lines (`[tool] Name {json cut at 120}`, `[result] …`, `[text] …`). `agent-run-trace.ts` reads them back into the same rows as structured events: tool chips and targets (paths relative to the runner's work directory), each result under the oldest call still waiting (Claude Code streams the next call before earlier results arrive), `[text]` as messages. An empty result left no line in those runs, so pairing after one can shift; a result with no call waiting shows on its own. Their results stay as cut as the runner stored them; the full text is in the transcript download.
- **Questions in the trace**: the run's questions (`cloud_agent_run_questions`) show as an `Ask` (or `Repo`) row in the turn that asked, placed by time among that turn's rows, with each part's chosen options and free text and the state. The question projection gains `askedInTurnId`; without it (older server) the turn comes from the `question` event's `turnId`.
- **Removed**: the old timeline, `RunPullRequests.tsx`, `RunRepositories.tsx`, `RunActivityCard`, `timelineItems` and its tests. Pushed heads and the `branch_pushed` lines are no longer shown (the pull request cards replace them); not built or tested and withheld paths are points of the result.
- **Tests**: web 27 files / 258 tests (route tests through the full-app router with a stubbed fetch: stages, spec and intent drawers, inline review, answered and open questions, cancel, re-run, delivery, stage jump); agent-runner 126; core protocol 5; server unit 135; `cloud-agent-runs.postgres.integration.test.ts` 19/19 and `cloud-agent-runs-questions.postgres.integration.test.ts` 16/16 on throwaway Postgres containers.
- **Deviations**: reads through `intent_read` (node, search) are not captured, since they answer markdown, not JSON; runs recorded before this change show no intent items. The runner change needs `docker compose up -d --build agent-runner` (after the server, which the watch mode already reloaded).
